# Design decisions and tradeoffs

**An explicit graph with durable state.** A finite Python transition map and typed state make failures and recovery inspectable. SQLite checkpoints each completed pipeline node; QA history persists separately from execution progress. A framework such as LangGraph could provide richer scheduling, but the current sequential workflow does not need that additional dependency.

**A local stack without paid keys.** Ollama runs `qwen3.5:4b`; FastEmbed provides CPU embeddings and Qdrant stores vectors locally. This avoids hosted inference credentials and database administration. The cost is model download size, memory use, and hardware-dependent latency and quality. Hosted free tiers would add accounts, quotas, and another availability dependency. Model weights retain their own licenses.

**Visible evidence and a conservative briefing fallback.** The model selects source sentence IDs; Python copies quotations and validates provenance and numerical values. A second pass through the same model screens support, adding latency and correlated error. If it rejects a briefing paraphrase, the application can substitute visibly labeled source excerpts and a warning. This keeps evidence inspectable but sacrifices synthesis; copying does not prove relevance or correct interpretation. Rejected limitations are removed, with an explicit missing-evidence note when none remain. QA has no such fallback and abstains on rejected support. Schema and provenance failures still fail closed after one repair attempt.

**Hybrid retrieval with a limited evaluation claim.** Dense search handles paraphrases; BM25 preserves exact scientific terms. Reciprocal-rank fusion combines rankings without treating their scores as probabilities. References are searched only when requested. The developer-constructed smoke evaluation compares all three modes on one paper; it cannot establish general superiority. A cross-encoder reranker is deferred until broader evidence justifies its cost.

**One paper and transparent PDF extraction.** Topic search selects one candidate while retaining the alternatives. pdfplumber provides page geometry and inspectable section/chunk heuristics with modest setup. The parser records warnings and refuses unreadable PDFs. OCR, reliable table/figure understanding, and cross-paper synthesis are deferred; richer document models and synthesis would introduce additional dependencies and evidence problems.

**A bounded canonical retry for arXiv HTTP 406.** Some official API requests succeeded with documented minimal URL syntax while equivalent parameterized requests returned 406. For alphanumeric topic terms, one alternate request removes unnecessary quotes/default parameters and preserves the terms, Boolean operator, requested result bound, and any recent-date sorting. Successful normalization is disclosed in session warnings and only real API metadata is cached. This is not a substitute search source or a claim that all topics work; an unsuccessful equivalent retry remains a source failure.

**Local interaction and portable results.** The CLI and `web.py` browser adapter use the same agent and data-directory lock. The web server binds to `127.0.0.1:8765` and keeps job progress in memory, so jobs are not a durable queue. Pipeline checkpoints and completed exchanges survive server restarts; interrupted work is resumed or retried from saved sessions. The exported HTML is a portable evidence reader. GitHub Pages serves saved reports only, with no public inference. Authentication and multi-user hosting are outside scope.

With more time: build a held-out evaluation across papers and layouts, compare support review with human judgments, measure fallback usefulness, and use those results to prioritize parsing, retrieval, or generation improvements.
